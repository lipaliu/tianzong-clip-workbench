# CUTLINE · 天总切片工作台

把“完整直播 → 选择聊播/带货 → 大模型自然发现内容灵感 → 原片预览 → 逐字精剪 → 下载无字幕切片 / ChatCut 精修”包装成一套可操作的网页工作流。

## 当前版本

这是第一版交互产品壳，使用已经逐字阅读并人工校准的天总样片演示完整审核流程。

已实现：

- 响应式三步工作台：上传与类型、内容地图、文字精剪
- 聊播/带货两套任务入口与内容规则
- 大模型自然发现数量的内容灵感，不预设、不保底、不凑数
- 左侧灵感、中间可播放原片、右侧逐字稿的主编操作台
- 逐句保留/删除、按时间码定位与无字幕原始切片生成演示
- 无字幕 MP4 下载与 ChatCut 精修两个交付出口
- 明确区分演示数据和尚未接入的真实能力

尚未接入：

- 真正的视频上传、对象存储与任务队列
- 自动逐字转写、说话人识别和词级时间戳
- 大模型候选发现、人设匹配和结构化时间轴生成
- ChatCut OAuth、真实工程创建与云端导出

## 推荐线上架构

```text
浏览器
  ↓ 签名直传
R2 / S3 对象存储
  ↓ 创建异步任务
API + PostgreSQL + 任务队列
  ├─ 转写 Worker：词级时间戳 / 说话人区分
  ├─ 语义 Worker：候选发现 / 评分 / 人设校准
  ├─ 媒体 Worker：代理视频 / 字幕 / 预览成片
  └─ ChatCut 适配层：OAuth / 资产 / 可编辑时间轴
```

用户登录的是产品自己的账号，不需要 Codex。Codex 只用于开发、调试和沉淀工作流。如果用户要在自己的 ChatCut 中继续精剪，再单独授权 ChatCut。

候选数量不是一个后台配置项。生产接口只返回 `candidates[]`，页面上的“本场发现 N 条灵感”直接使用 `candidates.length`；不另设目标值、最低数、最高数或补齐逻辑。

## 模型与算力

首版以质量为最高优先级，每一层都使用当前任务最强的合适模型：

- 转写：使用最高质量转写；多人对话使用带说话人区分的转写模型。
- 全场发现、内容聚类、候选判断、逐字结构和最终终审：统一使用旗舰模型 `gpt-5.6-sol`。
- 采用三遍主编制：高召回发现、结构精剪、独立终审。任何一遍不成立的内容都不为凑数量而保留。

模型选择参考 [OpenAI Models](https://developers.openai.com/api/docs/models)，转写参考 [GPT-4o mini Transcribe](https://developers.openai.com/api/docs/models/gpt-4o-mini-transcribe)。

GPU 与 Token 不是二选一：

- 调用托管模型时，模型供应商已经承担 GPU，产品按文本/音频 Token 或对应计费单位付费。
- 自建转写或大模型时，才需要自行购买和调度 GPU。
- 普通裁切、拼接、字幕烧录和低清代理，MVP 用 CPU Worker 足够；高并发硬编码、视觉跟踪或自动构图再考虑 GPU。

完整成本由五部分组成：模型 Token、音频转写、对象存储与流量、媒体处理时长、ChatCut 额度。

## 产品原则

这不是黑盒式“一键自动剪”。候选片段必须依次经过：

1. 内容地图与候选发现
2. 同主题聚类和价值排序
3. 事实、数字、SKU、功效与版权复核
4. 人工逐字确认保留/删除后生成干净原片切片
5. 输出默认无字幕、无效果、保留原声；需要包装时再进入 ChatCut

“找到素材的时间窗”“发布安全时间窗”“最终剪辑时间轴”必须分开保存。
