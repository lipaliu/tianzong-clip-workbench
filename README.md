# CUTLINE · 天总切片工作台

把“完整直播 → 逐字转写 → 高价值候选 → 人设校准 → 人工审核 → ChatCut 可编辑时间轴”包装成一套可操作的网页工作流。

## 当前版本

这是第一版交互产品壳，使用已经逐字阅读并人工校准的天总样片演示完整审核流程。

已实现：

- 响应式任务工作台与直播处理流程
- 聊播/带货候选切片、评分、风险提醒与筛选
- 候选片段详情、结构建议和自然语言修改意见
- 批量选择与 ChatCut 交付状态演示
- 上传入口、处理进度、运行架构与成本说明
- 明确区分演示数据和尚未接入的真实能力

尚未接入：

- 真正的视频上传、对象存储与任务队列
- 自动逐字转写、说话人识别和词级时间戳
- 大模型候选发现、人设匹配和结构化时间轴生成
- ChatCut OAuth、真实工程创建与云端导出

## 推荐线上架构

```text
浏览器
  ↓ 签名直传
R2 / S3 对象存储
  ↓ 创建异步任务
API + PostgreSQL + 任务队列
  ├─ 转写 Worker：词级时间戳 / 说话人区分
  ├─ 语义 Worker：候选发现 / 评分 / 人设校准
  ├─ 媒体 Worker：代理视频 / 字幕 / 预览成片
  └─ ChatCut 适配层：OAuth / 资产 / 可编辑时间轴
```

用户登录的是产品自己的账号，不需要 Codex。Codex 只用于开发、调试和沉淀工作流。如果用户要在自己的 ChatCut 中继续精剪，再单独授权 ChatCut。

## 模型与算力

推荐分层调用：

- 转写：`gpt-4o-mini-transcribe`；多人对话可使用带说话人区分的转写模型。
- 候选初筛：`gpt-5.6-luna`，适合批量、成本敏感的段落分类。
- 终审与重组：`gpt-5.6-terra`，平衡质量与成本。
- 复杂或高风险内容：按需升级到 `gpt-5.6-sol`，不建议全量使用。

模型选择参考 [OpenAI Models](https://developers.openai.com/api/docs/models)，转写参考 [GPT-4o mini Transcribe](https://developers.openai.com/api/docs/models/gpt-4o-mini-transcribe)。

GPU 与 Token 不是二选一：

- 调用托管模型时，模型供应商已经承担 GPU，产品按文本/音频 Token 或对应计费单位付费。
- 自建转写或大模型时，才需要自行购买和调度 GPU。
- 普通裁切、拼接、字幕烧录和低清代理，MVP 用 CPU Worker 足够；高并发硬编码、视觉跟踪或自动构图再考虑 GPU。

完整成本由五部分组成：模型 Token、音频转写、对象存储与流量、媒体处理时长、ChatCut 额度。

## 产品原则

这不是黑盒式“一键自动剪”。候选片段必须依次经过：

1. 内容地图与候选发现
2. 同主题聚类和价值排序
3. 事实、数字、SKU、功效与版权复核
4. 语义粗剪和节奏包装
5. 只听声音、静音看画面、正常播放三遍验收

“找到素材的时间窗”“发布安全时间窗”“最终剪辑时间轴”必须分开保存。


```bash
npm run build
```
