# 天总直播切片系统 · 内测 BETA 1.0

这是只服务天总直播的内部切片工作台，不是通用剪辑产品。首屏先让编导完成最重要的动作：上传整场直播、选择聊播或带货、开始生成内容地图。团队对天总聊播、带货、语气、节奏、内容边界与成片价值的长期研究，不在首页抢占功能，而是在候选召回、逐字精剪与输出判断中给出具体依据。

给不懂开发的助理使用的最短接线步骤见：[上线接线手册](docs/上线接线手册.md)。

## 首屏工作方式

首页不是传播页，而是一个项目制工作台，交互接近 AI 对话框：

1. 页面最先出现的是一只两步工作流对话框：左侧 STEP 1 上传整场直播，STEP 2 选择聊播或带货；粉色表示当前步骤，白色表示待选步骤。
2. 功能入口下方用一组横向铺开的半透明竖幅人物广告牌和两行模型说明，交代当前使用的是天总专属模型。
3. 选中聊播时，右侧说明系统如何保住观点、因果链、姐妹共鸣和人物反差；选中带货时，立即切换为单一购买理由、画面证明、人群边界和可信成交。
4. 文件名包含日期时自动识别日期；否则采用文件时间，为本场创建“6月17日 · 聊播切片”这类项目名。
5. 每上传并分析一场完整直播，就新增一个独立项目；项目列表显示日期、原片名、类型、状态和最终切片数。
6. 候选数量来自模型自然判断，有多少返回多少，不设目标数、不凑数。

研究样本量、批次、时长校准和版本过程都不出现在首页。人物照片作为底层视觉资产，不挤压上传入口；其余人物理解在候选、逐字精剪与输出过程中出现。

## 系统内的人物模型

人物理解不是一套摆在首页给人阅读的“剪辑规则”，而是系统在工作过程中解释每次选择的依据。天总真正稀缺的不是某一句商业金句，也不是单纯的颜值、身材或“霸总”标签，而是五种身份能够在同一个人身上自然、连续地切换：

1. **实战老板**：有公司、品牌、直播、电商、供应链与用人经验，讲的是做过以后才知道的机制、成本和边界。
2. **强姐姐**：面对女性观众，嘴快、结论直接、主意很正，能把含糊的问题迅速讲明白。
3. **视觉吸引**：漂亮、会穿、会展示，稳定的镜头吸引力本身就是内容，而不只是干货外面的包装。
4. **搞笑女**：随时唱跳、做饭翻车、逗猫，也会在装得最像霸总的时候突然失败。
5. **脆弱真实**：会谈自卑、原生家庭、爱情、失去与疲惫，不把自己包装成一个永远强大、永远正确的人。

最准确的切片定位是：

> 一个有实战能力、嘴很快、主意很正的女老板；她帮姐妹把赚钱、关系和生活讲明白，又总在最有权威感的时候被现实拆台。

这也是系统所有选择的总原则：不能只剪“女老板讲干货”，也不能把她拆成颜值、毒舌、搞笑或脆弱中的任何一个单一标签。真正有辨识度的候选，往往同时包含两种以上状态，尤其是“先建立权威，再被现实拆台”的反差弧线。

她稳定表达的价值观包括：判断要有理由，商业要尊重长期成本，女性要把钱、能力与生活的掌控感握在自己手里；可以强势，但不能只剩狠话；可以漂亮，但不能丢掉真实；可以脆弱，也不等于失去行动力。

她的核心观众不是泛商业受众，而是想把赚钱、关系和生活想明白的女性。有人先被外形和反差吸引，有人先被直接结论和实战经验吸引，最后留下来的原因是：她既能给方法和判断，也像一个会失误、会难过、会开玩笑的真实姐姐。

首页折叠说明只需要简短概括核心人格、稳定价值观与核心观众。完整理解要在流程里变成可核验的证据：候选页说明“为什么是天总”，列出这条内容承载的人物状态和原句依据；输出页说明“这条保住的人物线”，让编导看到最终成片留下了什么，而不是再读一遍抽象人设介绍。

## 研究基线

后台研究使用的是可追溯的首轮基线，而不是抽象的“AI 懂内容”：

- 909 个本地视频文件，约 10.685 GiB
- 827 个去重作品 ID；其中 82 组重复均来自“可乐 + 蛋壳椰”
- 32,594 行逐字稿，259,410 个非空白字符
- 47 个已返回分析批次，覆盖逐字稿 97.85%；另有 1 个批次缺失
- 2,469 条处理器返回的原始段落记录，仍需去重与质检，不能写成“2,469 条已验证成片”
- 5 条真实原视频的首轮时长校准：4 条 standard 平均 30.57 秒、中位数 30.84 秒；1 条 deep_dive 为 122.34 秒

五条校准样本只是初始基线，不代表平台最佳时长，也不能覆盖所有内容类型。近期直播与近期切片拥有最高权重；早期官方作品只作低权重风格参考，因为她当前已经不再完全沿用早期做法。

这些数据是后台研究证据，不是主页传播文案。成品界面应呈现系统已经学会的天总人物模型；研究样本量与处理过程留在版本说明、内部文档或审计界面中。

## 当前真实链路

已实现：

- ChatGPT 式单入口首屏：左侧两步上传 / 类型选择，右侧完成当前动作并发送分析
- 多张人物竖图以半透明广告牌方式铺在模型说明底层，两行正文保持清楚；不添加装饰视频，也不让人物研究盖过上传入口
- 聊播 / 带货切换时动态展示两套不同的天总切片认知：前者剪清判断如何成立，后者剪清购买理由如何被证明
- 按直播日期创建项目，使用 D1 持久化项目名、原片名、类型、状态和切片数
- 浏览器把 MP4 / MOV 通过短时签名地址直传腾讯云私有 COS；Sites 服务端只负责签名代理，不接触 OpenAI、COS 或私有核心密钥
- 腾讯云 API、PostgreSQL 与异步 Worker：记录项目、上传、任务、进度、候选、反馈和重渲染版本
- 腾讯云 Worker 使用独立持久工作目录（`/var/data/tianclip`）：同时容纳源文件副本、音频、稀疏 / 密集帧和预览；长期资产仍只进私有 COS
- 豆包 BigASR 负责中文逐字稿、说话人与绝对时间码；`gpt-5.6-sol` 按固定版本的私有天总 Skill 进行最终编导判断
- 全时间轴先做约每 12 秒与镜头变化帧的语义地图，再以约每 2 秒与镜头变化帧做视觉反向补召回；视觉模型先只看画面和时间码，再确定性绑定邻近逐字稿
- 每个候选再用安全窗内的密集静帧、视觉事件与带说话人的逐字稿二次校正切口，同时生成带原声的连续安全窗，明确要求团队正常播放复核
- 每个任务都从私有 COS 读取 Skill，核对固定版本和 SHA-256；事实层、剪辑计划、决策账本必须通过该 Skill 自带的三个 Schema，否则任务失败关闭
- 无伪造历史数据的真实项目列表，分析结束后回写本场自然发现的候选数量
- 候选页的“为什么是天总”人物证据，以及输出页的“这条保住的人物线”
- 五种身份连续切换的人物模型，以及反差弧线对选题与落刀的约束
- 响应式三步工作台：上传与类型、内容地图、文字精剪
- 聊播 / 带货两套任务入口与对应判断依据
- 数量自然生成的候选列表：不预设目标、不设保底、不凑数
- 左侧候选、中间原片预览、右侧逐字稿的审核工作台
- 每个候选的选择依据、编辑适配分拆解、时长依据、优先级、事实门禁与校准状态
- 逐句保留 / 删除后由 FFmpeg 生成一个新的版本；旧版本上的人工确认不会继承到新版本，团队必须完整播放当前版本并用版本 ID 再次确认
- 确认后出现四张交付卡：MP4、SRT、XML 三种本地格式可多选，ChatCut 保持独立操作
- 可导入并本地校验 SRT 字幕；导入后的原文件可与 XML 时间线草案一起下载，XML 供 Premiere / DaVinci Resolve 重连原片

仓库仍保留少量静态设计样例，用于页面在没有任务时的布局回归；真实上传启动后，页面只读取处理服务返回的候选、逐字、时间码、粗剪和版本状态。处理服务不可用时会明确失败，不会用样例数据替代本次结果。

## 自然候选与编辑适配分

候选数量不是后台目标值。生产接口只返回 `candidates[]`，页面直接显示实际的 `candidates.length`。模型判断有 40 条就返回 40 条，有 100 条就返回 100 条；没有自然语义闭环的内容不会为了看起来“产出多”而补齐。

页面中的分数叫“编辑适配分”，不是爆款概率、流量承诺或商业价值预测。当前拆解维度为：

- 前 3 秒钩子：20
- 情绪强度：20
- 金句密度：20
- 共鸣度：15
- 逻辑完整：15
- 互动 / 反转：10

总分只帮助编导排序：75 分及以上进入精剪，60–74 分作为备选，60 分以下淘汰。事实风险、商品数字、功效表述、版权风险或音画质量问题可以直接否决高分候选。

## 时长与落刀原则

最新 Skill 的参考模式为：

- `micro`：12–27 秒
- `standard`：28–35 秒
- `deep_dive`：90–130 秒
- `custom`：不设硬窗口

这些区间是编辑参考，不是硬切线。候选必须先保住自然语义闭环：超过 75 秒不会自动拆分，五条样本的整体均值也不会被当作目标值。系统应分别保存“发现素材时间窗”“发布安全时间窗”和“最终剪辑时间轴”。

## 后台研究与版本发布

持续学习发生在后台研究流程，不是前台新增一个“投喂入口”。团队会继续与 Codex 逐条研究天总直播、切片和逐字稿，补充新观察、纠正旧结论并修订判断；前台工作台只展示已完成评审、已发布的学习结果。

每次知识升级都走完整的可追溯链路：

1. **后台研究对话**：围绕新增材料和真实案例提出观察、反例与待验证问题。
2. **判断修订**：更新人设、内容类型、话术、时长、风险与近期权重，记录新旧规则差异。
3. **回测校准**：用固定评测集、真实原片和人工成片回测，确认修订没有破坏已有正确判断。
4. **版本发布**：记录学到了什么、改了哪些规则、影响哪些判断，再从内测 BETA 1.0 演进到正式 1.0、2.0、3.0 及后续版本。

编导在前台逐句保留 / 删除或调整落刀后，系统可以记录“建议时间轴与人工成片的差异”，但这只是一条回标候选。它必须经过后台评审、归因和回测，才有资格进入下一知识版本，不能由一次操作直接改写生产规则。

每次发布都应保留可回滚的知识快照、评测集和变更说明。未经评审的新结论只进入研究区，不能自动成为生产规则。

## 真实能力边界

代码层已接通上传、私有对象存储、异步任务、转写、全场稀疏语义地图、密集视觉反向召回、候选级画面与逐字稿精筛、私有 Skill 推理、候选粗剪、逐字删留、版本化重渲染、人工音画门禁和 MP4 / SRT / XML 本地交付。正式运行仍必须在 OpenAI、火山引擎、腾讯云 COS、腾讯云服务器和 Sites 录入真实凭证；没有这些凭证，线上站点只是一套不能处理原片的前台，不能称为已经上线。

当前边界：

- 视觉层会扫描整条时间轴，并用密集静帧做补召回和候选二审，但仍不宣传成模型连续逐帧看完两小时；连续动作、细微表情、口型、音画同步和最终精确落刀由候选安全窗与人工正常播放确认。
- 转写保留说话人级时间段，不假装拥有 API 没有返回的高置信词级时间戳；逐字与人名仍需团队复核。
- 浏览器会在 4.9GB 以下使用单次 COS PUT，超过后自动切换为 64MiB 分片、逐片重试与失败中止；当前内部总上限为 9GB，已覆盖 8,242,271,965 字节的 7 月 3 日回归原片。
- 第一轮用现有腾讯云 2 核 2GB 实例做单任务串行链路验收，并配置 Swap；它是零新增费用的验证机，不是性能承诺。真实原片回归若出现 OOM、磁盘峰值超过 80% 或处理时效不可接受，再升级至 2 核 4GB 或 2 核 8GB。
- 当前只运行一个 Worker；未来需要并行处理时，应拆分独立 Worker 与独立工作目录，不能直接把单机 Worker 无状态扩容。
- 私有核心当前版本为内部发布候选，已固定版本与 SHA、并且失败关闭，但仍需用已知直播回归和新直播盲测后再扩大账号范围。
- ChatCut 授权与工程写入尚未接通；“进入 ChatCut”仍只说明独立精修交付，不会伪装成已经创建工程。
- 尚未建设商业计费、自动知识版本发布、跨客户权限和大规模并发运维；本阶段只面向可信的小团队内测。

## 当前部署架构

```text
浏览器
  ↓ Sites 服务端 HMAC 代理签发上传
腾讯云 COS 私有对象存储
  ↓ 腾讯云 API 创建异步任务
腾讯云 PostgreSQL + Worker（Docker Compose）
  ├─ 资源：现有 2 核 2GB 实例先做单任务串行验收；以真实峰值决定升级
  ├─ 豆包 BigASR：中文逐字稿 / 说话人 / 绝对时间码
  ├─ GPT-5.6 Sol + 私有核心：整场文字召回 / 稀疏与密集画面补召回
  ├─ 豆包 Seed 2.0 Lite：逐候选原生音视频证据复核
  ├─ GPT-5.6 Sol + 同一私有核心：最终去重 / 切口 / 人设与风险校准
  ├─ 媒体：FFmpeg 粗剪 / 逐字删留重渲染 / 版本化预览
  ├─ 知识版本层：研究对话 / 判断修订 / 回测 / 规则快照 / 发布与回滚
  └─ ChatCut 适配层：授权 / 资产 / 可编辑时间轴
```

用户登录产品自己的账号，不需要登录 Codex。若要把片段继续送进个人 ChatCut，再单独完成 ChatCut 授权。

## 内部登录

正式站点在 Cloudflare Worker 最外层执行内部账号校验。未登录访问首页、接口、静态脚本或媒体资源时，都只会收到登录窗口或 `401`；账号配置不会进入浏览器脚本。

- `INTERNAL_AUTH_CREDENTIALS`：服务端 Secret，JSON 对象格式，可配置多个内部用户名，例如 `{\"editor-a\":\"strong-password\"}`。
- `INTERNAL_AUTH_SESSION_SECRET`：服务端 Secret，至少 32 个随机字符，用于签发 12 小时有效的 HttpOnly、SameSite 会话 Cookie。
- 登录尝试会按访问来源和用户名分别写入 D1 原子限流记录，15 分钟窗口内达到 5 次后暂时锁定。
- 生产值只通过 Sites 运行时变量配置；仓库和 `.env.example` 不保存真实账号或密码。

本次内部候选版把模型职责明确锁定：豆包 BigASR 标准版 `volc.bigasr.auc` 负责中文逐字稿、说话人与绝对时间码；`gpt-5.6-sol` 强制加载私有天总核心，负责整场召回、画面补召回和最终编导判断；`doubao-seed-2-0-lite-260428` 只复核已经召回的候选原声视频。`gpt-4o-transcribe-diarize` 仅是 BigASR 明确失败后的可审计转写后备。模型名、私有核心版本和 SHA 都由服务端校验，任何核心不符就停止任务，不静默退回通用 Prompt。普通裁切、拼接、代理和封装由腾讯云服务器上的 FFmpeg 使用 CPU 完成，不消耗模型 Token。

数据边界也必须说清楚：原片与私有核心文件长期放在私有 COS；工作时，压缩中文音轨会发送给豆包 BigASR，候选原声视频及当前判断所需规则会发送给豆包 Seed 2.0 Lite，当前任务所需的核心规则、逐字稿和抽帧会发送给 OpenAI。Responses 请求使用 `store: false`，不代表数据从未离开自有服务器。内测前必须分别确认 OpenAI 与火山引擎项目的数据保留设置。

## 产品门禁

每个候选依次经过：

1. 全场内容地图与自然候选发现
2. 同主题聚类、去重与编辑适配排序
3. 事实、数字、SKU、功效、版权与音画质量复核
4. 人工逐字确认保留 / 删除及对应理由
5. 确认后勾选需要下载到本地的 MP4、SRT、XML，可同时选择；进入 ChatCut 精修是独立交付动作，不进入本地批量下载
