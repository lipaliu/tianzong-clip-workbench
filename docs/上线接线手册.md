# 天总直播切片系统：上线接线手册（助理版 · 腾讯云）

这份手册只解决一件事：把已经写好的前台、私有天总切片核心和处理服务真正接通，让天总团队可以在网上上传整场直播并检阅候选。

> **这份手册在 2026-08-07 重写过。** 更早的版本写的是 Render + Cloudflare R2，与代码不符——代码在 7 月底已经搬到腾讯云。如果你手上有旧版打印件或截图，全部作废。

## 先看结论

仓库和前台已经存在。助理需要准备并登录 4 个后台：

1. [OpenAI Platform](https://platform.openai.com/)：`gpt-5.6-sol` 强制加载私有天总 Skill，做最终召回、评分、去重和编导判断。
2. [火山引擎](https://console.volcengine.com/)：豆包 BigASR 负责中文逐字稿、说话人与时间码；豆包 Seed 2.0 Lite 负责候选窗原生音视频复核；豆包 Seed 2.0 Pro 可作为编导模型。
3. [腾讯云 COS](https://console.cloud.tencent.com/cos)：私有对象存储桶，保存直播原片、私有核心、审计结果和候选预览。
4. [腾讯云 CVM](https://console.cloud.tencent.com/cvm)：一台云服务器，用 Docker 跑 API、PostgreSQL、异步 Worker 和 FFmpeg。

前台继续使用现有 Sites 项目。你不需要购买 GPU，也不需要让天总团队登录 Codex。

> **没有填完真实凭证，系统就不能真实运行。** 页面能打开不等于已经接通模型、存储和剪辑。生产服务会在缺少凭证、私有核心缺失或校验值不一致时直接停止，不会用演示数据假装成功。

真实生产链路已经固定为：

```text
整场直播
→ 豆包 BigASR：中文逐字稿 / 说话人 / 绝对时间码
→ 编导模型 + 私有天总 Skill：整场文字召回
→ 豆包 Seed 2.0 Lite：逐候选原生音视频复核
→ 编导模型 + 同一份私有天总 Skill：综合所有证据作最终编导判断
→ FFmpeg：生成无字幕粗剪
→ 团队在线播放、删话、改切点、下载
```

编导模型可选 OpenAI `gpt-5.6-sol`、火山 `doubao-seed-2-0-pro-260215`，或两家同时跑做对比。**两家同时跑就是两份钱**，费用差别很大，见最后一节。

豆包音视频复核属于"模型看过候选的原声视频"，不冒充逐帧连续人工审核。每条候选仍然必须由团队完整、正常倍速播放后才能批准。

## 密钥安全：只遵守这一条

所有密钥只填到服务器上的 `.env.tencent` 或 Sites 的运行时变量中：

- 不发在微信或聊天消息里；
- 不写进 README、截图、代码和 GitHub；
- 不使用 `NEXT_PUBLIC_*` 保存密钥；
- 曾经在聊天中出现过的测试密码，上线前全部换新。

账号登录和二次验证由账号持有人本人完成。出现密钥输入框时，由账号持有人在页面里直接粘贴。

## 第 1 步：准备两个模型后台

### 1.1 OpenAI API

1. 登录 [OpenAI Platform](https://platform.openai.com/)。
2. 在 Billing 中绑定支付方式并购买 API 额度。ChatGPT/Codex 订阅 **不包含** OpenAI API 用量。
3. 建一个单独项目，例如 `TianClip Internal`，方便单独查看费用。
4. 在该项目里创建 API Key，暂存在密码管理器里。
5. 设置预算或用量告警。告警用于提醒，不要把它当作绝对的硬停机保证。

官方说明：[创建并使用 API Key](https://platform.openai.com/docs/quickstart/make-your-first-api-request)、[预付费说明](https://help.openai.com/en/articles/8264644-how-can-i-set-up-prepaid-billing)。

### 1.2 火山引擎 / 豆包

在火山控制台完成三件事：

1. 在"语音技术 / 录音文件识别"开通大模型标准版资源 `volc.bigasr.auc`，保存 `App Key` 和 `Access Key`。
2. 在"火山方舟"开通 `doubao-seed-2-0-lite-260428`（音视频复核）。
3. 在"火山方舟"开通 `doubao-seed-2-0-pro-260215`（编导模型），创建并保存 `ARK API Key`（两个模型共用同一个 Key）。

BigASR 处理压缩后的完整中文音轨；Seed 2.0 Lite 只处理已经召回的候选安全窗，不把两小时原片反复整段送入音视频模型。

### 数据边界必须如实确认

原片、私有核心文件和派生素材长期保存在你自己的私有 COS；但模型工作时，服务端会把**压缩中文音轨**交给豆包 BigASR，把**候选原声视频、候选逐字稿和当前模式所需的私有规则**交给豆包 Seed 2.0 Lite，并把**当前任务所需的核心规则、转写文本和抽取画面**交给编导模型。代码对支持的 Responses 请求设置 `store: false`，这不等于"数据从未离开自有服务器"，也不应被宣传成零留存。

上线前由账号持有人分别确认 OpenAI 与火山引擎的数据控制、地域和保留政策。不要把私有核心全文、原片或任何 API Key 交给测试账号。

## 第 2 步：建立腾讯云 COS 私有桶

### 2.1 创建私有桶

1. 登录腾讯云，进入 **对象存储 COS → 存储桶列表 → 创建存储桶**。
2. 名称填 `tianclip-private`（腾讯云会自动追加你的 APPID，最终形如 `tianclip-private-1300000000`，**后面填变量时要用带 APPID 的完整名字**）。
3. 地域建议选 **新加坡 ap-singapore** 或离服务器最近的地域；**服务器和桶必须同地域**，跨地域会产生额外流量费并拖慢处理。
4. 访问权限选 **私有读写**。绝对不要选公有读。

### 2.2 创建只访问这个桶的子账号密钥

1. 进入 **访问管理 CAM → 用户 → 新建用户 → 自定义创建**，选"可访问资源并接收消息"。
2. 只勾选 **编程访问**，不要给控制台登录权限。
3. 权限策略选择"按策略"，新建一条自定义策略，只允许这一个桶的对象读写。
4. 创建完成后立即保存 `SecretId` 和 `SecretKey`；SecretKey 关闭页面后不能再次查看。

S3 兼容端点格式为 `https://cos.<地域>.myqcloud.com`，例如 `https://cos.ap-singapore.myqcloud.com`。

> **变量名沿用 `R2_*` 前缀。** 代码里这些名字是内部 API 名，不是说还在用 Cloudflare。改名要动很多处并有配置漂移风险，所以保留原名。填腾讯云的值就对了。

### 2.3 配置浏览器直传所需的 CORS

在 `存储桶 → 安全管理 → 跨域访问 CORS 设置` 添加规则：

- **来源 Origin**：`https://cutline-tianzong.lipaliu514.chatgpt.site`（换正式域名时要加新域名的**完整 origin**，不能带路径，不能只写域名后缀）
- **操作 Methods**：`GET`、`PUT`、`HEAD`
- **Allow-Headers**：`Content-Type`、`Range`、`x-amz-meta-sha256`、`x-amz-meta-project-id`
- **Expose-Headers**：`ETag`、`Content-Length`、`Content-Range`、`Accept-Ranges`
- **超时 Max-Age**：`3600`

`ETag` 必须保留在 Expose-Headers：大文件会自动走分块上传，浏览器完成每个分片后必须读到该响应头，服务端才会逐片核对编号、大小和 ETag。缺少它时系统会明确失败并中止上传，不会把不完整对象交给 Worker。

### 2.4 清理未完成的分片

在 `存储桶 → 基础配置 → 生命周期` 增加一条规则：前缀 `uploads/`，**删除未完成的分块上传，1 天**。

程序正常报错时会主动中止分片；这条规则负责清理由断网、关浏览器或进程崩溃留下的孤儿分片。不清理会持续占用存储费。

## 第 3 步：把私有天总核心放进 COS

这一步是整个产品的根基，不是普通附件。

1. 找到文件（在移动硬盘 `lipa 2024/天总/核心备份/`）：

   `tianzong-video-clipping-1.2.3-private.1.skill`

2. 在 COS 桶中建立 `private-core` 目录。
3. 上传，并确认最终对象键 **一字不差**：

   `private-core/tianzong-video-clipping-1.2.3-private.1.skill`

4. 核对 SHA-256（在 Mac 终端运行 `shasum -a 256 文件名`，结果必须完全一致）：

   `f5caa9d679bc40fda1222c7b448c37f14465d8baa9a5c3c0661367b8e7b13d06`

> **这三样东西必须描述同一个文件**：对象键里的版本号、上面这个 SHA-256、以及后面 `TIANCLIP_CORE_VERSION` 填的 `1.2.3-private.1`。
>
> Worker 会先校验下载对象的 SHA-256，再核对压缩包内 `manifest.json` 的版本号。任何一项不符，任务立即失败关闭，不会退回通用 Prompt。**历史上这里出过错**：曾经把 1.2.0 的哈希配给 1.2.3 的文件名，结果每个任务都失败且看不出原因。配完务必按第 6 步验收。
>
> 硬盘上还有 1.2.0 / 1.2.1 / 1.2.2 三个旧版本，**不要传错**。

天总团队只操作前台，不需要拿到或下载这个私有核心。

## 第 4 步：让服务器能访问 OpenAI（大陆节点必做）

腾讯云大陆节点无法直连 `api.openai.com`。仓库自带一个窄通道中转，部署在 Cloudflare Pages：

**已部署地址：`https://tianclip-openai-relay.pages.dev/v1`**（可用 `/healthz` 确认存活）

它只转发 `/v1/models`、`/v1/responses`、`/v1/audio/transcriptions` 三个路径，要求请求头带 `OAI-Sites-Authorization`，并且**不在中转里保存任何 OpenAI Key**（Key 由服务器随请求带上）。

需要做的：

1. 在密码管理器生成一个不少于 32 位的随机串，作为中转口令。
2. 在 Cloudflare Pages 项目 `tianclip-openai-relay` 的环境变量里，设置 Secret `RELAY_AUTH_TOKEN` 为这个值。
3. 服务器 `.env.tencent` 里的 `OPENAI_SITES_BYPASS_TOKEN` 填**完全相同**的值。
4. `.env.tencent` 里 `OPENAI_BASE_URL` 填 `https://tianclip-openai-relay.pages.dev/v1`。

如需重新部署中转，在 `infra/openai-relay-pages/` 目录运行：

```sh
npx wrangler pages deploy public --project-name tianclip-openai-relay --branch main --commit-dirty=true
```

> 如果服务器选在**腾讯云香港或新加坡**节点，可以直连 OpenAI，这一步可以跳过，`OPENAI_BASE_URL` 保持默认 `https://api.openai.com/v1` 即可。**推荐选境外节点，少一层依赖。**
>
> 如果只用豆包当编导（`editorMode` 选火山），完全不需要这一步。

## 第 5 步：开服务器并部署

### 5.1 买机器

在腾讯云买一台 CVM：

- 系统：**Ubuntu 22.04 或 24.04**
- 规格：**首轮内测 2核4GB 起**（不是 2核2GB）
- 系统盘：**至少 100GB**
- 地域：与 COS 桶同地域
- 安全组：只放行 `22`（SSH）和 `443`（HTTPS）

> **为什么 100GB 盘。** 处理 7.7GiB 原片时，磁盘上会同时存在：从 COS 下载的完整源文件、分段 FLAC 音频、每 12 秒的稀疏帧、每 2 秒的密集帧、以及每条候选的预览。加上 Docker 镜像本身，50GB 会很紧张。
>
> **为什么 4GB 内存。** 之前的文档写 2核2GB 可以起步，那是没跑过真实原片的估计。FFmpeg 两次全片解码加密集抽帧，2GB 很容易 OOM（日志里表现为 exit 137）。多花的钱远少于反复排查的时间。
>
> **5 小时以上的直播**要再上一档（4核8GB）并把盘加到 200GB，同时注意系统内部上传上限是 9GB。

### 5.2 初始化

SSH 登录服务器，用 root 运行：

```bash
curl -fsSL https://raw.githubusercontent.com/lipaliu/tianzong-clip-workbench/main/scripts/bootstrap-tencent.sh | bash
```

这个脚本会安装 Docker、FFmpeg，建 4GB Swap，并把仓库克隆到 `/opt/tianclip`。

### 5.3 写生产密钥

在服务器上创建 `/opt/tianclip/.env.tencent`，权限设为 `600`：

```bash
touch /opt/tianclip/.env.tencent && chmod 600 /opt/tianclip/.env.tencent
```

以 `processor/.env.example` 为模板填写。必须填的值：

| 变量 | 填什么 |
|---|---|
| `POSTGRES_DB` | `tianclip` |
| `POSTGRES_USER` | `tianclip` |
| `POSTGRES_PASSWORD` | 新生成的强密码 |
| `DATABASE_URL` | `postgresql://tianclip:上面的密码@postgres:5432/tianclip` |
| `DATABASE_SSL` | `false`（容器内网连接，不需要 TLS） |
| `API_DOMAIN` | 你给 API 用的域名，例如 `api-tianclip.你的域名.com` |
| `INTERNAL_API_KEYS` | `{"sites-proxy":"新生成的64位随机串"}` |
| `R2_ENDPOINT` | `https://cos.ap-singapore.myqcloud.com`（按实际地域） |
| `R2_ACCESS_KEY_ID` | 腾讯云 SecretId |
| `R2_SECRET_ACCESS_KEY` | 腾讯云 SecretKey |
| `R2_BUCKET` | 带 APPID 的完整桶名，如 `tianclip-private-1300000000` |
| `R2_REGION` | `ap-singapore`（按实际地域） |
| `OPENAI_API_KEY` | OpenAI 项目 API Key |
| `OPENAI_BASE_URL` | 中转地址，或境外节点直连默认值 |
| `OPENAI_SITES_BYPASS_TOKEN` | 与 Pages 的 `RELAY_AUTH_TOKEN` 相同（直连则留空） |
| `DOUBAO_ASR_APP_KEY` | 火山语音控制台 App Key |
| `DOUBAO_ASR_ACCESS_KEY` | 火山语音控制台 Access Key |
| `DOUBAO_ARK_API_KEY` | 火山方舟 API Key |
| `TIANCLIP_CORE_S3_KEY` | `private-core/tianzong-video-clipping-1.2.3-private.1.skill` |
| `TIANCLIP_CORE_SHA256` | `f5caa9d679bc40fda1222c7b448c37f14465d8baa9a5c3c0661367b8e7b13d06` |
| `TIANCLIP_CORE_VERSION` | `1.2.3-private.1` |

其余带默认值的变量（模型名、超时、分片大小、心跳间隔、`WORK_DIRECTORY` 等）照 `.env.example` 原样复制，**不要改**。

### 5.4 解析域名并启动

把 `API_DOMAIN` 的 A 记录解析到服务器公网 IP，然后：

```bash
cd /opt/tianclip && docker compose --env-file .env.tencent -f docker-compose.tencent.yml up -d --build
```

Caddy 会自动申请 HTTPS 证书。首次启动需要几分钟拉镜像和编译。

> **不要用 compose 里那个 `tunnel` 服务当生产入口。** 它是 cloudflared 的临时隧道，地址随机、每次重启就变，一断线前台就连不上。它只适合临时调试。生产走 Caddy + 你自己的域名。

### 5.5 常用运维命令

```bash
docker compose --env-file .env.tencent -f docker-compose.tencent.yml logs -f worker
```

```bash
docker compose --env-file .env.tencent -f docker-compose.tencent.yml ps
```

更新代码后重新部署：

```bash
cd /opt/tianclip && git pull --ff-only origin main && docker compose --env-file .env.tencent -f docker-compose.tencent.yml up -d --build
```

## 第 6 步：在 Sites 填前台运行时变量

打开现有 Sites 项目的运行时变量设置。以下值只放服务端：

| Sites 变量 | 填什么 |
|---|---|
| `PROCESSOR_API_URL` | `https://你的 API_DOMAIN` |
| `PROCESSOR_KEY_ID` | `sites-proxy` |
| `PROCESSOR_API_SECRET` | 与服务器 `INTERNAL_API_KEYS` 内完全相同的那个随机串 |
| `INTERNAL_AUTH_CREDENTIALS` | 内部账号 JSON，例如 `{"tianzong":"新生成的强密码"}` |
| `INTERNAL_AUTH_SESSION_SECRET` | 另一个不少于 32 字符的随机串 |

注意：

- `PROCESSOR_API_SECRET` 与服务器内部签名 Secret 是同一个值；
- `INTERNAL_AUTH_SESSION_SECRET` 是**另一个**值，不要混用；
- `INTERNAL_AUTH_CREDENTIALS` 可以配多个账号，每人一个独立账号；
- 填完后保存新版本并重新部署 Sites，旧部署不会自动获得新配置。

## 第 7 步：验收

### 7.1 基础健康检查

浏览器打开：

1. `https://你的 API_DOMAIN/healthz` → 应包含 `ok: true`
2. `https://你的 API_DOMAIN/readyz` → 应包含 `ready: true`

`ready: true` 不只表示 API 活着：它同时确认 PostgreSQL、私有 COS 里的固定版本核心、以及最近 120 秒内确实有 Worker 报活。

**如果 `/readyz` 返回 503，最常见的原因就是私有核心的键名或 SHA-256 填错了。** 先回第 3 步逐字符核对。

然后打开 Sites：

1. 未登录时应只看到登录窗口；
2. 用内部测试账号登录；
3. 上传按钮可选文件；
4. 上传后出现真实阶段和进度，而不是固定倒计时；
5. 服务器 Worker 日志出现本次任务；
6. COS 出现本次原片、代理或候选文件；
7. 本次 `artifacts/<project>/<job>/provider-routing.json` 中：
   - `transcription.effectiveProvider` 应为 `doubao`；
   - `candidateAvReview.completedCandidateCount` 应大于 0；
   - `finalEditorial.privateCoreBound` 必须为 `true`。

如果任一项显示 fallback，先当作接线失败处理，不要拿降级结果冒充完整多模型验收。

### 7.2 查这一场花了多少钱

任务跑完后：

```
GET https://你的 API_DOMAIN/v1/jobs/<jobId>/cost
```

返回本场的分环节花费、切出的总秒数、以及每秒成片单价。

**如果某个环节显示 `priced: false`，说明那个模型还没有价目表**（例如换用了未登记的模型）。系统会如实标注"未定价"而不是记 0，此时 `cnyPerDeliveredSecond` 会是 `null`——缺一条腿的单价会偏低，所以宁可不给。

### 7.3 已知直播回归

用移动硬盘上两场已经研究过的直播，确认系统重复出已确认过的正确判断。

**6 月 17 日聊播** — `已转码_竺天天_2026年6月17日21时48分4秒_原画F.mp4`

- 类型选"聊播"；
- 候选数由内容自然产生，不应固定为某个目标数；
- 检查"带货是长线的"这句话被保留；
- 检查中间其他人无关的"我想做什么电商……"对话没有破坏天总观点；
- 逐字稿、切点和预览必须能回到真实原片时间码。

**7 月 3 日带货** — `已转码_天总_2026年7月3日19时58分58秒_蓝光F.mp4`

- 类型选"带货"；
- 检查购买理由、人群边界、产品展示和成交信息是否互相证明；
- 所有价格、数字、SKU、功效和承诺必须能在原声或画面中找到证据。

### 7.4 盲测

再选一场此前没有放入研究材料的新直播：

1. 先让系统自然召回全部合格候选，不给它规定条数；
2. 团队逐条标记"保留 / 删除 / 调整"，并写一句原因；
3. 记录三类问题：漏掉了什么、错选了什么、切点差在哪里；
4. 检查标题和摘要有没有把策划概括冒充天总原话；
5. 反馈进入下一版核心的人工评审与回测，不能由一次操作直接改写生产规则。

通过"已知回归 + 新直播盲测"后，才把账号发给更多团队成员。

## 视觉识别的真实边界

这套系统会看画面，但**当前不做全时间轴的独立视觉召回**：

1. 全场先做中文逐字稿召回，选出候选；
2. 每条候选生成带原声的连续"安全窗"粗剪；
3. 用豆包 Seed 2.0 Lite 对这个安全窗做原生音视频复核，专门找动作、细微表情、语气、场外插话、商品展示和音画反转；
4. 编导模型再次强制加载同一份私有 Skill，综合所有证据决定保留、拒绝、切口与删话；
5. 编导必须正常倍速看完整个安全窗，确认人物动作、说话人、音画同步和真实切点。

**这是有意的设计，不是缺陷。** 全场每 2 秒抽帧送视觉模型的成本极高，收益不成比例。

代价要如实说明：**纯画面才能发现的素材（做饭翻车、突然唱跳、试吃表情、举起产品那一下），系统结构上选不出来**，需要人工补。

系统会分别记录 `nativeAudioVideoInputReviewed`、`continuousFrameByFrameReviewed=false` 和 `humanNormalPlaybackRequired=true`，不得把任何机器证据冒充最终人工验片。

### 实测单价（2026-08-07，基于 6 月 17 日那场 2 小时 52 分）

| 编导模型 | 单场 | 切出 | **每秒成片** | 每小时直播 |

费用里服务器和存储的摊销占豆包方案的约三分之一，**一个月剪 20 场以上才划算**；只剪三五场的话，每场摊到的固定成本比模型费还高。

## 常见故障只看这张表

| 页面现象 | 最可能原因 |
|---|---|
| `/readyz` 返回 503 | **优先查私有核心**：对象键、SHA-256、版本号三者必须描述同一个文件 |
| "真实分析服务尚未配置" | Sites 缺少 `PROCESSOR_API_URL / KEY_ID / API_SECRET` |
| 返回 401 或"签名无效" | Sites 的 Key ID / Secret 与服务器 `INTERNAL_API_KEYS` 不一致 |
| 浏览器上传报 403 或 CORS | COS 跨域规则没有加入当前 Sites 的完整 origin，或 Expose-Headers 缺 `ETag` |
| "私有核心校验失败" | 传了旧版本（硬盘上还有 1.2.0/1.2.1/1.2.2），或 SHA 填错 |
| 任务一直排队 | Worker 没启动，或 `.env.tencent` 不完整；看 `logs -f worker` |
| `ENOSPC` / no space left | 磁盘满；扩容系统盘 |
| Worker exit 137 / OOM | 内存不足；升到 2核4GB 或 4核8GB 后重跑 |
| OpenAI 请求超时或连不上 | 大陆节点未配中转，或 `OPENAI_SITES_BYPASS_TOKEN` 与 Pages 的 `RELAY_AUTH_TOKEN` 不一致 |
| OpenAI quota / billing 错误 | Key 所属项目未充值或额度用完 |
| 豆包转写直接失败 | `App Key / Access Key / volc.bigasr.auc` 有一项未开通或填错；查 `provider-routing.json` 是否已降级 |
| 豆包音视频复核失败 | 方舟 Key 无模型权限或 Seed 2.0 Lite 未开通；系统会明确记录并降级，不冒充已看视频 |
| 费用接口显示 `priced: false` | 该模型没有登记价目表，属如实标注；要补价请改 `processor/src/pricing.ts` |
| `healthz` 正常但任务失败 | API 活着不代表模型、COS、核心和 Worker 都可用；看本次 Worker 日志 |
