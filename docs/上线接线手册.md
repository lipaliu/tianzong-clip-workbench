# 天总直播切片系统：上线接线手册（助理版）

这份手册只解决一件事：把已经写好的前台、私有天总切片核心和处理服务真正接通，让天总团队可以在网上上传整场直播并检阅候选。

## 先看结论

仓库和前台已经存在。助理需要准备并登录 4 个后台：

1. [OpenAI API](https://platform.openai.com/)：`gpt-5.6-sol` 强制加载私有天总 Skill，做最终召回、评分、去重和编导判断。
2. [火山引擎](https://console.volcengine.com/)：豆包 BigASR 负责中文逐字稿、说话人与时间码；豆包 Seed 2.0 Lite 负责候选窗原生音视频证据复核。
3. [Cloudflare](https://dash.cloudflare.com/)：R2 私有桶保存直播原片、私有核心、审计结果和候选预览，并给模型签发短期取件地址。
4. [Render](https://dashboard.render.com/)：运行 API、PostgreSQL、异步 Worker 和 FFmpeg。

Render 部署时会读取现有 GitHub 仓库；如果 Render 首次要求 GitHub 授权，只需按页面提示允许它访问 `lipaliu/tianzong-clip-workbench`，不需要另外准备代码。

前台继续使用现有 Sites 项目。你不需要购买 GPU，也不需要让天总团队登录 Codex。

> **没有填完真实凭证，系统就不能真实运行。** 页面能打开不等于已经接通模型、存储和剪辑。生产服务会在缺少凭证、私有核心缺失或校验值不一致时直接停止，不会用演示数据假装成功。

真实生产链路已经固定为：

```text
整场直播
→ 豆包 BigASR：中文逐字稿 / 说话人 / 绝对时间码
→ GPT-5.6 Sol + 私有天总 Skill：整场文字召回
→ GPT-5.6 Sol：全片稀疏与密集画面反向补召回
→ 豆包 Seed 2.0 Lite：逐候选原生音视频复核
→ GPT-5.6 Sol + 同一份私有天总 Skill：综合所有证据作最终编导判断
→ FFmpeg：生成无字幕粗剪
→ 团队在线播放、删话、改切点、下载或进入 ChatCut
```

豆包音视频复核属于“模型看过候选的原声视频”，不冒充逐帧连续人工审核。每条候选仍然必须由团队完整、正常倍速播放后才能批准。

## 密钥安全：只遵守这一条

所有密钥只填到 Render 或 Sites 的 **Environment / Secrets / 运行时变量** 中：

- 不发在微信或聊天消息里；
- 不写进 README、截图、代码和 GitHub；
- 不使用 `NEXT_PUBLIC_*` 保存密钥；
- 曾经在聊天中出现过的测试密码，上线前全部换新。

账号登录和二次验证由账号持有人本人完成。登录完成后，可以让 Codex继续代为点击和接线；出现密钥输入框时，由账号持有人在页面里直接粘贴。

## 第 1 步：准备两个模型后台

### 1.1 OpenAI API

### 助理要做什么

1. 登录 [OpenAI Platform](https://platform.openai.com/)。
2. 在 Billing 中绑定支付方式并购买 API 额度。ChatGPT/Codex 订阅 **不包含** OpenAI API 用量。
3. 建一个单独项目，例如 `TianClip Internal`，方便单独查看费用。
4. 在该项目里创建 API Key。
5. 把 Key 暂存在密码管理器里；后面只粘贴到 Render 的 `OPENAI_API_KEY`。
6. 设置预算或用量告警。告警用于提醒，不要把它当作绝对的硬停机保证。

官方说明：[创建并使用 API Key](https://platform.openai.com/docs/quickstart/make-your-first-api-request)、[预付费说明](https://help.openai.com/en/articles/8264644-how-can-i-set-up-prepaid-billing)。

### 这里为什么需要 OpenAI

- `gpt-5.6-sol`：读取整场逐字稿和抽帧证据，执行聊播 / 带货的私有天总规则；
- `gpt-5.6-sol`：在豆包音视频证据回来后再次加载同一份私有 Skill，决定保留、拒绝、切口、删话、标题和评分；
- `gpt-4o-transcribe-diarize`：只作为豆包 BigASR 明确失败后的安全转写后备，并在台账中记录发生过降级。

OpenAI 产生的是模型 Token 费用；普通裁切、转码和预览由 Render 上的 FFmpeg 用 CPU 完成，不消耗 Token。

### 1.2 火山引擎 / 豆包

助理在火山控制台完成两件事：

1. 在“语音技术 / 录音文件识别”开通大模型标准版资源 `volc.bigasr.auc`，保存：
   - `App Key`
   - `Access Key`
2. 在“火山方舟”开通模型 `doubao-seed-2-0-lite-260428`，创建并保存：
   - `ARK API Key`

这三个值后面分别填入 Render：

- `DOUBAO_ASR_APP_KEY`
- `DOUBAO_ASR_ACCESS_KEY`
- `DOUBAO_ARK_API_KEY`

不要把它们发到聊天、微信、GitHub 或前端。BigASR 处理压缩后的完整中文音轨；Seed 2.0 Lite 只处理已经召回的候选安全窗，不把两小时原片反复整段送入音视频模型。

### 数据边界必须如实确认

原片、私有核心文件和派生素材长期保存在你自己的私有 R2；但模型工作时，服务端会把**压缩中文音轨**交给豆包 BigASR，把**候选原声视频、候选逐字稿和当前模式所需的私有规则**交给豆包 Seed 2.0 Lite，并把**当前任务所需的核心规则、转写文本和抽取画面**交给 OpenAI。代码对支持的 Responses 请求设置 `store: false`，这不等于“数据从未离开自有服务器”，也不应被宣传成零留存。

上线前由账号持有人分别确认 OpenAI 与火山引擎的数据控制、地域和保留政策；如果内部政策要求 Zero Data Retention，应先确认对应项目真实生效，再上传未公开直播。不要把私有核心全文、原片或任何 API Key 交给测试账号。

## 第 2 步：建立 Cloudflare R2 私有桶

### 2.1 创建私有桶

1. 登录 Cloudflare。
2. 进入 **Storage & databases → R2 → Create bucket**。
3. 桶名填写：`tianclip-private`。
4. 保持 **Public Development URL 关闭**，不要打开 `r2.dev` 公网访问。

### 2.2 创建只访问这个桶的凭证

1. 在 R2 Overview 找到 **Manage API Tokens**。
2. 创建一个 R2 API Token。
3. 权限选 **Object Read & Write**。
4. 范围选 **Specific bucket only → tianclip-private**。
5. 创建后立即保存以下三项；Secret 关闭页面后不能再次查看：

   - `Access Key ID`
   - `Secret Access Key`
   - S3 endpoint，格式为 `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`

官方说明：[R2 S3 凭证](https://developers.cloudflare.com/r2/get-started/s3/)、[R2 Token 权限](https://developers.cloudflare.com/r2/api/tokens/)。

### 2.3 配置浏览器直传所需的 CORS

在 `tianclip-private → Settings → CORS policy` 粘贴：

```json
[
  {
    "AllowedOrigins": [
      "https://cutline-tianzong.lipaliu514.chatgpt.site",
      "http://localhost:3000"
    ],
    "AllowedMethods": ["GET", "PUT", "HEAD"],
    "AllowedHeaders": [
      "Content-Type",
      "Range",
      "x-amz-meta-sha256",
      "x-amz-meta-project-id"
    ],
    "ExposeHeaders": [
      "ETag",
      "Content-Length",
      "Content-Range",
      "Accept-Ranges"
    ],
    "MaxAgeSeconds": 3600
  }
]
```

如果以后换正式域名，要把新域名的 **完整 origin** 加进 `AllowedOrigins`，例如 `https://clip.example.com`；不能带路径，也不能只写 `example.com`。CORS 更新偶尔需要约 30 秒生效。

`ETag` 必须保留在 `ExposeHeaders`：大文件会自动走 R2 multipart，浏览器完成每个分片后必须读到该响应头，服务端才会逐片核对编号、大小和 ETag。缺少它时系统会明确失败并中止 multipart，不会把不完整对象交给 Worker。

官方说明：[R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/)。

### 2.4 缩短未完成分片的清理时间

R2 默认会在 7 天后自动中止未完成的 multipart；本项目的大文件分片可能占用数 GB，内测桶应在 **Object lifecycle rules** 里给前缀 `uploads/` 增加一条“Abort incomplete multipart uploads after 1 day”的规则。程序在正常报错时也会主动 abort；这条规则负责清理由断网、关浏览器或进程崩溃留下的孤儿分片。

官方说明：[R2 Object lifecycles](https://developers.cloudflare.com/r2/buckets/object-lifecycles/)。

## 第 4 步：用 Render Blueprint 建后端

### 4.1 创建 Blueprint

1. 登录 Render，并连接有权访问本仓库的 GitHub 账号。
2. 点击 **New → Blueprint**。
3. 选择仓库 `lipaliu/tianzong-clip-workbench`，分支选 `main`。
4. Blueprint Path 填：

   `processor/render.yaml`

5. 点击 **Deploy Blueprint**。

现有 Blueprint 会一次创建：

- `tianclip-postgres`：项目、上传、任务、候选和反馈记录；
- `tianclip-processor-api`：接收前台请求并签发 R2 临时上传地址；
- `tianclip-processor-worker`：异步转写、视觉筛查、候选判断和 FFmpeg 预览；
- `tianclip-worker-scratch`：只挂在 Worker 的 30 GB 临时工作盘，挂载点为 `/var/data/tianclip`。

API 不挂盘。原片、私有核心、事实层、计划、台账和成片仍以私有 R2 为长期来源；Worker 盘只容纳某次任务同时存在的源文件副本、FLAC 音频、稀疏帧、密集帧和候选预览。Worker 正常完成或受控失败时会删除本次目录；如果进程被强制终止，下一次启动会先清掉未完成的临时目录，再从 R2 重新开始，避免重试时一份份累积源文件。

官方说明：[创建 Render Blueprint](https://render.com/docs/infrastructure-as-code)。

### 4.1.1 为什么先配 30 GB，而不是继续用默认临时盘

已经拿到的真实回归原片约为 **7.7 GiB**。处理期间不是只保存这一份文件，峰值还会同时包含：

- R2 下载到本机的完整源文件；
- 分段 FLAC 音频；
- 约每 12 秒的稀疏帧；
- 约每 2 秒加镜头变化的密集帧；
- 候选安全窗预览和 FFmpeg 中间输出。

30 GB 是当前单 Worker、单任务串行内测的起步容量，不是随便估出来的长期上限。验收目标是跑完 7.7 GiB 回归原片时，Render 的 **Disk Usage 峰值保持在 24 GB 以下（80%）**，并且硬重启后能重新处理而不因旧临时目录耗尽磁盘。Render 的磁盘容量以后可以增加、不能减少，因此先固定 30 GB；如果峰值达到 24 GB，直接扩到 50 GB，不要等磁盘写满以后再处理。

本轮容量预算按十进制 30 GB 计算：

| 同时存在的内容 | 预留 |
|---|---:|
| 7.7 GiB 原片副本 | 约 8.3 GB |
| FLAC、稀疏帧、每 2 秒密集帧、镜头变化帧、候选预览 | 最多先按 12 GB 观察 |
| 文件系统、单个正在写入的 FFmpeg 输出和异常波动余量 | 约 9.7 GB |

这张表是部署容量预算，不是对派生文件真实大小的伪造测量。第一次完整回归必须从 Metrics 记录真实峰值；若派生内容超过预留，按 80% 门槛扩盘。启动前清理保证硬崩溃留下的上一份 8.3 GB 原片不会和下一次重试叠加，因此 30 GB 的余量才成立。

网页在 4.9GB 以下使用单个 R2 预签名 PUT；超过后自动使用 64MiB multipart。分片只以 `File.slice` 形成当前小块，不会把整场直播读入浏览器内存；同时上传 3 片，每片最多重试 3 次，失败会调用 abort。服务端会以 R2 `ListParts` 结果核对完整分片数量、每片大小和 ETag，再允许合并。当前内部总上限为 9GB，已覆盖 **8,242,271,965 字节**的 7 月 3 日回归原片，并为 30GB 工作盘上的音频、密集抽帧、预览与成片保留余量。若以后要接近 20GB，先把工作盘扩到至少 50GB 并重做容量回归。

Render 官方说明：持久盘只有挂载路径下的数据会保留，而且一个有盘服务只能运行单实例；磁盘可以增加但不能缩小。[Persistent Disks](https://render.com/docs/disks)

### 4.1.2 Standard 是初测下限，不是已证明的最终规格

Blueprint 当前把 Worker 设为 `standard`，即 **2 GB RAM / 1 CPU**。这是可信小团队、一次只跑一场直播的最低内测配置：

- 可以用于验证完整链路和资源峰值；
- FFmpeg 的两次全片解码、密集抽帧和候选逐条转码会串行执行，7.7 GiB 原片可能需要较长时间；
- 目前不能承诺处理耗时，必须以 6 月 17 日、7 月 3 日和 7.7 GiB 原片的真实日志为准；
- 初测通过标准是：无 OOM、无磁盘写满、无 Worker 重启循环，任务最终完成，内存峰值低于约 1.6 GB（80%）。

出现以下任一情况，Worker 直接升级为 `pro`（4 GB RAM / 2 CPU），不用改业务代码：

1. 日志出现 OOM / exit 137，或内存持续超过 80%；
2. 单场任务出现反复重启，排除密钥和模型错误后仍失败；
3. 全片解码与代理生成耗时不能满足团队当天交付；
4. 经常同时排队两场以上直播。

磁盘达到 80% 只扩磁盘；CPU / 内存不够才升级实例。Render 的 Metrics 页面可查看 CPU、内存、磁盘用量和磁盘活动。`Standard` 与 `Pro` 的当前规格见 [Render Instance Types](https://render.com/docs/compute-plans)，监控项见 [Service Metrics](https://render.com/docs/service-metrics)。

挂盘后这个 Worker 不能横向扩成多个实例，也不再是零停机部署。如果以后需要两场以上真正并行，不能把 `numInstances` 改成 2；要拆成各自拥有独立工作盘的 Worker，或者改造为不依赖单盘的任务执行架构。API 没有挂盘，因此 API 仍可独立扩容。

| Sites 变量 | 填什么 |

## 第 6 步：5 分钟验收

### 6.1 基础健康检查

在浏览器分别打开：

1. `https://<Render API 地址>/healthz`
2. `https://<Render API 地址>/readyz`

正确结果应分别包含：

- `ok: true`
- `ready: true`

`ready: true` 不只表示 API 进程活着：它同时确认 PostgreSQL、私有 R2
里的固定版本核心，以及最近 120 秒内确实有后台 Worker 报活。Worker
停机时 `/healthz` 仍可用于诊断 API，但 `/readyz` 会返回 503，而且新
分析任务会被拒绝，不会进入无人消费的队列。

然后打开 Sites：

1. 未登录时应只看到登录窗口；
2. 用内部测试账号登录；
3. 上传按钮可选文件；
4. 上传后出现真实阶段和进度，而不是固定倒计时；
5. Render 的 Worker 日志出现本次任务；
6. R2 出现本次原片、代理或候选文件；
7. 本次 `artifacts/<project>/<job>/provider-routing.json` 中：
   - `transcription.effectiveProvider` 应为 `doubao`；
   - `candidateAvReview.completedCandidateCount` 应大于 0；
   - `finalEditorial.model` 应为 `gpt-5.6-sol`；
   - `finalEditorial.privateCoreBound` 必须为 `true`。

如果任一项显示 fallback，先把它当作接线失败处理，不要拿降级结果冒充完整多模型验收。

### 6.2 已知直播回归测试

先用已经研究过的两场直播，确认系统在重复已经确认过的正确判断：

#### 6 月 17 日聊播

文件：`已转码_竺天天_2026年6月17日21时48分4秒_原画F.mp4`

- 类型选“聊播”；
- 候选数由内容自然产生，不应固定为 6、50 或其他目标数；
- 检查“带货是长线的”这句话被保留；
- 检查中间其他人的无关“我想做什么电商……”对话没有破坏天总观点；
- 检查能否在原片因果链成立的前提下，衔接到“电商需要学两年”；
- 逐字稿、切点和预览必须能回到真实原片时间码。

#### 7 月 3 日带货

文件：`已转码_天总_2026年7月3日19时58分58秒_蓝光F.mp4`

- 类型选“带货”；
- 检查购买理由、人群边界、产品展示和成交信息是否互相证明；
- 所有价格、数字、SKU、功效和承诺必须能在原声或画面中找到证据；
- 只说得热闹但没有单一购买理由、视觉证明或完整因果链的段落，不应被包装成高质量带货候选。

### 6.3 盲测

再选一场此前没有放入研究材料的新直播：

1. 先让系统自然召回全部合格候选，不给它规定条数；
2. 团队逐条标记“保留 / 删除 / 调整”，并写一句原因；
3. 记录三类问题：漏掉了什么、错选了什么、切点差在哪里；
4. 检查标题和摘要有没有把策划概括冒充天总原话；
5. 把反馈留在系统里，进入下一版核心的人工评审与回测，不能由一次操作直接改写生产规则。

通过“已知回归 + 新直播盲测”后，才把账号发给更多团队成员。

## 视觉识别的真实边界

这套系统会看画面，但不能宣传成“逐帧连续看完两小时直播”：

1. 全时间轴按固定间隔抽帧（当前约 12 秒一次）；
2. 镜头变化处额外抽帧；
3. 模型根据这些稀疏证据建立全场视觉事件地图；
4. 系统再用两次全片 FFmpeg 解码取得约每 2 秒的密集帧与镜头变化帧；视觉模型先不看逐字稿，只凭画面和时间码补召回容易被文字漏掉的动作、反差与翻车；
5. 视觉候选确定后，系统才把邻近逐字稿绑定回来，并与私有 Skill 从文字召回的候选做证据级去重合并；
6. 每个合并候选先生成带原声的临时候选视频，通过短期 R2 地址交给豆包 Seed 2.0 Lite 做原生音视频模型复核，专门找动作、细微表情、语气、场外插话、商品展示、唱跳和音画反转；
7. GPT-5.6 Sol 再次强制加载同一份私有天总 Skill，综合逐字稿、密集静帧、既有视觉事件和豆包音视频证据，最终决定保留、拒绝、切口与删话；
8. 每个保留候选生成包含上下文和原声的连续“安全窗”粗剪预览；
9. 编导必须正常倍速看完整个安全窗，确认人物动作、细微表情、说话人、音画同步和真实切点。

豆包确实接收候选原声视频，不是只读文字；但“原生音视频模型输入”仍不等于人工逐帧连续观看。只有人工在页面确认完整正常播放后，候选才可以标为“视听已核验”。系统会分别记录 `nativeAudioVideoInputReviewed`、`continuousFrameByFrameReviewed=false` 和 `humanNormalPlaybackRequired=true`，不得把任何机器证据冒充最终人工验片。

## 费用归谁

| 费用 | 由什么产生 | 在哪里付 |
|---|---|---|
| OpenAI API | 私有 Skill 最终编导判断、全场文字召回、抽帧视觉理解；豆包 ASR 失败时的转写后备 | OpenAI Platform |
| 火山引擎 | 豆包 BigASR 中文转写；Seed 2.0 Lite 候选原生音视频复核 | 火山引擎 |
| Render | API、Worker、PostgreSQL、FFmpeg CPU 运行时间 | Render |
| Cloudflare R2 | 原片 / 私有核心 / 预览的存储和读写操作 | Cloudflare |
| Sites | 前台托管、运行时与 D1，按当前账户方案为准 | Sites |
| ChatCut | 只有进入 ChatCut 精修或使用其付费能力时才产生 | ChatCut |

最容易混淆的一点：**OpenAI 与豆包各自按各自 API 计费；Render 是服务器费；R2 是存储费。** FFmpeg 裁切本身不消耗任何大模型 Token。

### Render 资源预算怎么估

- Worker `standard` 的计算费用、API `starter` 和 PostgreSQL `basic-256mb` 按 Render 当天价格页为准；
- 30 GB Worker 持久盘按 Render 2026 年 7 月公开的 **$0.25/GB/月** 约为 **$7.50/月**，按秒折算；价格变化时以 Render Dashboard 为准；
- R2 是长期对象存储，Worker 盘只是热处理空间，不要把原片长期堆在 Render 盘；
- 初测先付一台 Standard Worker，不先买 Pro；只有真实回归触发上面的 CPU / 内存门槛再升；
- 盘只能增不能减，所以 30 GB 是有意选择的起步值；达到 80% 时扩 50 GB。

当前计费口径可核对 [Render 官方费用说明](https://render.com/articles/how-much-does-cloud-application-hosting-cost-for-small-businesses) 和 [Render Pricing](https://render.com/pricing)。

## 常见故障只看这张表

| 页面现象 | 最可能原因 |
|---|---|
| “真实分析服务尚未配置” | Sites 缺少 `PROCESSOR_API_URL / KEY_ID / API_SECRET` |
| Render 返回 401 或“签名无效” | Sites 的 Key ID / Secret 与 Render `INTERNAL_API_KEYS` 不一致 |
| 浏览器上传报 403 或 CORS | R2 CORS 没有加入当前 Sites 的完整 origin，或 Header 不全 |
| “私有核心校验失败” | R2 对象 Key、文件或 SHA-256 有一个不一致 |
| 任务一直排队 | Render Worker 没启动，或 Worker 环境变量不完整 |
| `ENOSPC` / no space left on device | Worker 盘接近写满；先看 Disk Usage，达到 80% 就把 30 GB 扩到 50 GB |
| Worker exit 137 / OOM | Standard 2 GB 内存不足；升级 Worker 为 Pro 4 GB / 2 CPU 后重跑 |
| 重启后磁盘仍快速增长 | `WORK_DIRECTORY` 或磁盘挂载点不一致；两者都必须是 `/var/data/tianclip` |
| OpenAI quota / billing 错误 | API Key 所属项目未充值、额度用完或 Key 无效 |
| 豆包转写直接失败 | `App Key / Access Key / volc.bigasr.auc` 有一项未开通或填错；查看 `provider-routing.json` 是否已降级到 OpenAI |
| 豆包音视频复核失败 | 方舟 Key 无模型权限、临时 R2 地址不可取或 Seed 2.0 Lite 未开通；系统会明确记录并降级为密集静帧，不会冒充已看视频 |
| `healthz` 正常但任务失败 | API 活着不代表 OpenAI、R2、私有核心和 Worker 都可用；看本次 Worker 日志 |
